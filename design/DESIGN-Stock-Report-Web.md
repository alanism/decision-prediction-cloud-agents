# HTML Stock Report Design Standard

9 October 2026 · HTML is the primary reading and update format. PDF is optional.

## Editorial identity

Use the company’s common name as the main masthead: Meta, NVIDIA, Google, CrowdStrike or Bloom Energy. The ticker remains identifying metadata. Lead with a large centered serif name, sector, issue date and short editorial deck. Follow with a thin-rule section navigation and a clear research headline. Never reproduce the reference publication’s name or logo.

The supplied style reference informs cream paper (#fdfcf3), black ink, a restrained yellow signal (#ffc500), serif editorial text, sans-serif utility labels, square geometry and hairline rules. The supplied Andy Allen card informs honest, inspectable data, an inviting reading environment and reversible exploration. The report does not claim the adviser reviewed it. Its refinement comes from useful evidence and well-paced reading, not decorative scores or fictional simulations.

Screen layout is fluid, with a 1280px maximum publication width. It is not a fixed A4 facsimile. Large headings, generous paragraph spacing and two-column analysis work at wider widths; narrower screens receive single-column text and lenses. Dense tables have labeled horizontal-scroll regions. Use native typography and inline SVG; do not depend on external scripts, fonts or image servers.

Apply the requested six visual questions and five SQVID dimension pairs without implying that a conceptual drawing is a measured statistical chart.

Use this generic scaffold only with the current report’s own verified inputs. No private report examples are bundled.

## Evidence and calculations

Preserve the original source dates, market cutoffs, current educational research conclusions, units, assumptions and audit JSON bytes. A visual update does not refresh prices, reprice brokerage holdings, produce a calibrated forecast or create trade authority.

- Measured: dated public source observations
- Calculated: deterministic arithmetic that inherits input uncertainty
- Modeled: explicit assumptions and their computed results
- Forecasted: attributed forward statements with horizon and conditions

Brokerage observations without actual user verification are labeled “Observed · unconfirmed,” not Measured with a contradictory footnote. Calculated derivatives keep an unconfirmed-input caveat.

Do not blend different stock probability sets. Keep each report’s risk-return scenarios separate from its valuation grid when their definitions differ. Keep raw-Kelly-first and bounded-Kelly-first fractioning conventions distinct. The main and full companion retain the exact original numeric records.

## Useful chart interactions

Compatible native-button controls should reveal existing valuation cases and uniform account shocks. They highlight a case, expose its already reported values, restate the assumptions and allow deterministic reset. They do not recalculate financial outputs, change probabilities, alter saved assumptions, make API calls or place orders.

Use native buttons with explicit pressed state and readable labels. Tab plus Enter/Space follows standard button behavior. Optional Left/Right/Home/End navigation starts from the focused button, which may differ from the selected button. Keep focus predictable and show an accessible live readout. Source tables and full charts remain available without JavaScript.

Require deeply frozen interaction data and lookup-only results. Scripts must use textContent rather than HTML insertion, make no automatic network request and use no cookies or browser storage. External source links can navigate only when the reader activates them. Source/logic tests cannot establish real browser or assistive-technology behavior.

## Chart grammar

Use a Sankey only for conserved quantities and one width scale. Use zero-baseline bars for comparable amounts, with signed bars for negative cash flow. Label 2×2 diagrams as qualitative and scenario lines as sensitivities rather than history. Do not fabricate a time series, confidence/radar score, set size or probability to fill a visual slot. Generated drawings are explanatory; exact printed values carry the evidence.

## Portability

Each accepted report HTML should embed its final PNG, exact calculation JSON and useful audit material so saving the file preserves its essential evidence. Optional companions or print files need explicit delivery and verified links. No prior PDF, ZIP or report output is bundled in this repository.

The reusable Stock-Report-Web-Template.html contains the publication shell and inert metric/lens/figure/sketchnote components. Fill it only with company-specific supported material. Provide matching immutable JSON for any interaction controls. This is an authoring template, not runtime integration or a financial engine.
