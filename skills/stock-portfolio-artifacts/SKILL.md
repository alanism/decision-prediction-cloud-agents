# Cloud research artifact storage

Research works without holdings. Use only an explicit authorized existing private directory outside bundle, source and Git checkout. Never discover personal folders or accounts automatically. User-supplied CSV generally preserves structured fields better than screenshots; both need as-of dates, provenance and limitations. Stale, absent or partial evidence remains explicit; never invent holdings or confirm screenshot values automatically.

## Versions and identity

Use the report ID and reports/<id>/current.json pointer managed by the adapter. Each immutable versions/vNNNNNN revision includes report HTML, input and hash receipt. Preserve earlier versions. Update only relevant evidence/analysis while retaining accurate structure; create a new revision rather than overwriting history. No automatic publisher upload, schedule or delivery occurs.

## Full report and optional deep dive

Keep the anatomy's thirteen analytical areas, evidence sidebar, all eight simulated framework lenses and separate Page robustness note. The default HTML reading edition maps these areas into a current educational structure rather than reproducing prescriptive historical headings.

An explicitly requested six-page deep dive can use:
1. Research overview and central question
2. Business and moat: Porter, seven Powers, nine-block BMC
3. Financial engine: returns, margins, capex and cash flow
4. Market and competition: market definition, evidence and substitutes
5. Risk and hypothetical scenarios: downside, safety margins and model limits
6. Research implications, dissent, triggers and missing evidence

Retain the selected Monocle, Creative Giants or Ease Health design family. No private position plan or transaction conclusion is generated. Use immutable versions for deep dives too.

## Optional tracked-company list and scheduling

A user-owned tracked list can distinguish watchlist from explicitly confirmed holdings with last-confirmed/as-of dates. It is private data. Creating it or any refresh schedule requires the relevant user request and host authority. The supplied schedule example is inactive. Record exact timezone, cadence, source policy, destination, retention, confirmed setup receipt and first successful run separately. Never infer scheduling from a file's existence.
